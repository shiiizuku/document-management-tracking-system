# Frontend audit — 2026-10-04

Scope: `apps/web` at `ff06dca` plus the current, uncommitted `COMPLY` dialog and test edits. This is a source and targeted-test review of session behavior, data freshness, previews, accessibility, and validation coverage. It is not a rendered browser or assistive-technology audit. Existing working changes were preserved.

## Findings, in implementation order

| Priority | Finding | Evidence | Suggested change and proof |
| --- | --- | --- | --- |
| P1 — session privacy | **A failed logout still appears complete.** `useLogout` clears the query cache and navigates to `/login` in `onSettled`, including when the request never reached the API. The HTTP-only session cookie then remains valid; opening an authenticated route after connectivity returns can re-establish the same session. The current test asserts the misleading navigation on a failed request. | `apps/web/src/features/session/queries.ts:118-132`; `apps/web/test/session.test.tsx:121-132`; cookie clearing occurs only in `apps/api/src/modules/auth/session.service.ts:77-80`. | Keep immediate local data clearing, but show that sign-out could not be confirmed and offer retry once connected. If a completed logout must invalidate an already-issued token, add server-side revocation; clearing the cookie alone cannot do that. Test an offline request followed by a route revisit. |
| P2 — memory and stale preview | **Closing or switching a preview before its fetch resolves can leak its object URL.** `inlineContent()` creates the URL before the mutation resolves. The effect cleanup releases only `fetched`, which is still `null` if the viewer closes first. TanStack Query invokes per-call `mutate(..., { onSuccess })` callbacks only while the observer has listeners, so an unmounted viewer never takes ownership of a late result. A path switch can likewise leave the earlier result unreleased. Existing tests close only after the preview has loaded. | `apps/web/src/components/dts/inline-file-pane.tsx:61-74`; `apps/web/src/lib/api.ts:198-205`; installed `@tanstack/query-core/src/mutationObserver.ts:135-138,240-255`; `apps/web/test/attachment-preview.test.tsx:132-146`. | Own the async result in an effect with an abort/cancel flag; release a result that arrives after cleanup and release the displayed result on close or path change. Test a deferred response resolved after unmount and after switching paths. |
| P2 — data freshness | **A socket reconnection does not catch up missed changes.** The `connect` handler only updates an indicator; cache invalidation runs only for notifications received after connection. An open inbox or document list can stay stale after a temporary outage until focus or another event triggers a refetch. | `apps/web/src/features/realtime/use-realtime-sync.ts:51-59`; `apps/web/test/realtime-sync.test.tsx` covers live events but not reconnect catch-up. | Invalidate the inbox and affected document queries on reconnect, or use a cursor-based catch-up API. Test disconnect → server-side change → reconnect with no new socket event. |
| P2 — accessible navigation | **Document rows mimic links without native link behavior.** Table rows are focusable and accept Enter/Space but remain rows with no link target. Card and line views use `role="link"` on `article`/`li` with click handlers, so browser link actions such as opening a record in a new tab are unavailable. A screen reader also cannot identify the table row as a link. | `apps/web/src/components/dts/data-table.tsx:178-200`; `apps/web/src/components/dts/list-views.tsx:99-123,193-215`; `apps/web/src/features/documents/registry-screen.tsx:240-247`. | Put a real Next `Link` in each document's primary cell/card/line and retain row highlighting separately. Verify keyboard access, link announcement, and open-in-new-tab in a browser. |
| P3 — keyboard pattern | **The list-view selector declares a radio group but lacks radio keyboard behavior.** All three buttons remain in the Tab order and there is no arrow-key handler. | `apps/web/src/features/documents/document-list.tsx:37-64`. | Use a native radio group or a tested toggle/radio primitive with arrow-key behavior and one tab stop. Add keyboard tests for Left/Right and selection. |
| P2 — coverage gate | **The browser and accessibility acceptance gate is unfinished.** Unit tests cover the main screens, but the planned Playwright journeys, axe sweep, and responsive/browser matrix have not landed as a runnable CI gate. `apps/e2e/` and `docs/acceptance-scenarios.md` are untracked work in progress. | `docs/frontend-rebuild-plan.md` decision 8 and Testing section; `.github/workflows/ci.yml` runs unit/integration checks but no browser job. | Finish the in-progress harness, run incoming and outgoing journeys and critical-screen axe checks in CI, and record responsive checks at representative widths. |
