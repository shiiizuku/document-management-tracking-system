# Repository audit — 2026-10-04

Branch: `codex/repository-audit-2026-10-04` (created from `57762b1`). This is a code and delivery-readiness review, not a production penetration test. ## Recommended order

| Priority | Finding and evidence | Suggested implementation and proof |
| --- | --- | --- |
| P0 — before a pilot | **Production seeding can create accounts with public passwords.** `apps/api/src/database/seed.ts:61-84,116-127` falls back to a known administrator password and always inserts records and staff users with known passwords. The production guard only requires a configured Director (`apps/api/src/config/environment.ts`). The README currently relies on an operator to deactivate or change the other accounts. | Make production seeding require a nondefault initial administrator credential and omit development records/staff accounts. Keep local demo users behind an explicit development-only path. Test both environments and the production failure case; update the deployment instructions. Review any database already seeded in production for these accounts. |
| P1 — before deployment | **Infrastructure ports publish to all host interfaces by default.** `docker-compose.yml:31,47,69,83` publishes PostgreSQL, Redis, MinIO, its console, and ClamAV; `:143` publishes the API. The README asks operators to firewall or edit those mappings on a server. | Supply a production Compose override that leaves internal services unpublished and exposes only the intended reverse-proxy entry points, then document and verify the rendered production configuration. Keep development port mappings in a development profile or override. |
| P1 — readiness gate | **Audit retention decision is not implemented.** `docs/policy-register.md:35` records five years in the primary database, then relocation to a separate database with no purge; `docs/phase-7-sequencing.md:250` tracks the gap. | Agree on the archive database with IT, implement a repeatable and verifiable relocation job, preserve query/access and audit integrity, and test an old-record migration plus interruption/retry. Do not add a deletion path. |
| P1 — readiness gate | **Recovery objective has no rehearsal evidence.** `docs/policy-register.md:40` specifies a recovery point of at most five minutes and a two-to-four-hour restore, but reports no timed restore. The scripts and runbook exist. | Restore a representative backup from off-host storage into an isolated environment, verify database and object bytes plus application login/download, record actual recovery point and elapsed time, then fix any missed target. |
| P2 — user correctness | **Realtime reconnect does not reconcile missed events.** `apps/web/src/features/realtime/use-realtime-sync.ts:51-59` changes connection state on `connect`, but only invalidates queries on a new notification. A user who remains on an open screen through an outage can see stale data until another refetch. This is also identified in `docs/IMPLEMENTATION_STATUS.md`. | On reconnect, invalidate the inbox and relevant document list/detail queries or use a cursor-based catch-up endpoint. Add a test for events missed while disconnected and for repeated reconnects. |
| P2 — delivery gate | **Browser journey and accessibility coverage remain incomplete.** `docs/phase-7-sequencing.md:211-224` calls for acceptance scenarios, Playwright journeys, and an axe sweep. `apps/e2e/` and `docs/acceptance-scenarios.md` now exist as untracked work, but no runnable E2E workspace or CI job was present at audit start. | Finish the in-progress harness, run the incoming and outgoing journeys against the full stack in CI, and add browser/accessibility checks for the named screens. Keep a test database separate from development data. |
| P2 — performance evidence | **Search and upload capacity have not been measured against pilot data.** `docs/phase-7-sequencing.md:233-245` identifies the derived `PENDING` predicate, pilot-sized `EXPLAIN`, and load tests as outstanding. Uploads and downloads currently materialize whole files in memory (`apps/api/src/modules/files/files.controller.ts:50,92,124`; `apps/api/src/modules/files/minio-storage.adapter.ts:42-58`). | Generate representative volumes, record plans and latency for scoped searches and the pending dashboard, then exercise concurrent 25 MB uploads/downloads under a defined memory and latency target. Change indexes or streaming only where the measurements justify it. |
| P2 — developer experience | **The Windows formatting gate fails on checkout line endings.** With `core.autocrlf=true`, tracked TypeScript and YAML files are `i/lf w/crlf`, while `.gitattributes` pins LF only for `infra/**`, shell scripts, and Dockerfiles. `npm run quality` stopped at `format:check` with 275 warnings; the committed LF version of `apps/api/src/main.ts` passes Prettier. | Pin LF for source/config/text files in `.gitattributes` (or configure Prettier's line-ending policy consistently), then verify `npm run format:check` on a fresh Windows checkout and Linux CI without a bulk content rewrite. |
